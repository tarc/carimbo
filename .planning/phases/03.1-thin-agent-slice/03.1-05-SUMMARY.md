# Phase 3.1 Plan 05: the Python harness runs and grades decision cases Summary

## Decisions Made

- One `run_cases` with a `RunSpec` (RESEARCH Q6) instead of a decision-only runner.
- Guard tool calls are counted from `source: guard` calls in steps when present, otherwise from `outcome.guard.tool_call`, so a call recorded in both places is not counted twice.
- Cost totals in the summary are `null` when any response has no usable value, with `unpriced_cases` and `unpriced_incurred_cases` beside them.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `RunSpec.request_info` takes `(case, reference_date, overrides)`**
- **Found during:** Task 1
- **Issue:** The plan sketched `request_info(case)`, but extraction's request block also holds `reference_date` and `overrides`, and decision records hold `overrides` but no `reference_date`; one argument could not express both without a flag.
- **Fix:** `request_info` receives the same three arguments as `payload` and returns every request member except the traceparent and trace id the runner mints. Extraction records are identical to before.
- **Files modified:** python/src/carimbo_evals/runner.py
- **Commit:** 3bfcdc7

**2. [Process] Task 2 tests passed on arrival**
- The shared `run_cases` code already satisfied every Task 2 behavior, so no RED state existed and no source change was needed. The tests were committed as `test(03.1-05)` and act as regression pins.
