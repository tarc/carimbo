# Phase 3.1 Plan 09: POST /eval/decisions returns and records the agent's decision Summary

**Contract decision-1 at POST /eval/decisions, locked down exactly like the extraction route and composed over the existing gateway decorator stack, with bounded Agent configuration, one shared incurred-cost rule, and content-free invoke_agent / execute_tool spans on the request trace.**

## Performance

- **Duration:** 13 min (2026-10-22T03:12:39Z to 03:25Z for the code; SUMMARY and state follow)
- **Tasks:** 3 (1 tracer, 2 auto, all TDD)
- **Files:** 10 changed in the code commits (4 created, 6 modified)
- **Tests:** 51 new in Carimbo.Api.Tests (DecisionEndpointTests, DecisionTracingTests); `just dotnet-check` 1208 passed, 0 failed, format clean; extraction goldens unchanged

## Accomplishments

- **Tracer (Task 1).** A case id posted with a fixed traceparent comes back as the decision-1 body in the exact D-36 member order: `effective` (model, `agent-001`, max_steps, the SHA-256 of `schema/decision.model.schema.json`, tools_sha256, pricing version, cache mode, salt), `outcome` (status, decision, model_decision, decided_by, guard with its own recorded call, tool_failure, failure, raw_output), two steps (the first with four model tool calls and parsed argument objects), usage, cost and incurred cost as F8 strings that equal the step sums, latency and the trace id. The agent runs over the real Tools host in process and a scripted model.
- **Shared eval-route preamble (Task 1).** Auth, body binding (415, 413, strict bind), the three override checks and the owned-activity trace id moved out of `HandleAsync` into internal helpers used by both routes, and the incurred rule became `IncurredCost.Of(response, failureKind)` used by extraction attempts and decision steps. The 200 pre-existing Api tests and the 14 golden-response tests pass unchanged and `data/contract/eval-responses` is byte-identical.
- **Gating, validation and typed outcomes (Task 2).** 404 outside Development or Eval, without the key or without a gateway (the log names the condition, never a value); 401 before the body is read (a malformed body still gets 401); 415; 413 at the declared length; 400s keyed by field for contract_version, case_id (including `../policy`, `DC-001`, empty and 65 characters), overrides.model, cache_mode (unknown, and not-off on a host without a cache) and replicate_salt, and keyed `body` for `overrides.prompt_version`, `overrides.max_steps` and unknown members, none echoing the value and none making a model call. A refusal, a read_only cache miss and an unknown case id are all HTTP 200 typed outcomes.
- **Bounded configuration (Task 2).** `Agent:MaxSteps` outside 1..10, a non-positive `MaxTokens` or `ToolCallTimeoutSeconds`, and a `ToolsUrl` that is not http(s) on `localhost` or a loopback IP (`http://example.com`, `ftp://127.0.0.1`, a relative path, `http://10.0.0.5`) fail startup naming the setting; `http://[::1]:5090/mcp` and `http://localhost:5090/mcp` start.
- **Tracing (Task 3).** `AgentRunner` opens `invoke_agent carimbo-decision` around the run, so the `chat claude-haiku-4-5` spans of `TracingLlmGateway` parent under it, and one `execute_tool <name>` span per run call, the guard's included, tagged with `carimbo.agent.tool_source`. The run span carries counts, status, outcome, cause, decided_by and guard_overridden by wire name only. A failing tool is an error span with `error.type` set to the error kind. `tracing.AddSource(AgentTelemetry.SourceName)` registers the source.

## Decisions Made

See `key-decisions`. One flagged fact worth restating: the GenAI specification (read 2026-10-22) says an `execute_tool` span SHOULD be Internal and an `invoke_agent` span SHOULD be Client and MAY be Internal for an in-process agent. The plan fixed Client for tool spans and Internal for the run; both are kept, and the reason (each tool call crosses a process boundary to the Tools host) is in the `AgentTelemetry` doc comment.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Model-invented tool names kept out of spans**
- **Found during:** Task 3
- **Issue:** The plan tags `gen_ai.tool.name` on every execute_tool span, but a tool name the model made up (an unlisted name is a recorded `unknown_tool` failure) would put model text into a span name and tag, against D-31 and T-03.1-34.
- **Fix:** The span name and tag use the catalog tool name, or `unknown` for anything else (the rule `ToolFailed` already applies to the decision reason). Test `A_tool_name_the_model_invented_never_reaches_a_span_name_or_a_tag`.
- **Files modified:** dotnet/src/Carimbo.Agent/AgentRunner.cs
- **Commit:** 12e8d0a

**Total deviations:** 1 auto-fixed (Rule 2). **Impact:** none on the plan's contracts.
