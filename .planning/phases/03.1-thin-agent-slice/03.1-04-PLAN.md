# Phase 3.1 Plan 04: the Anthropic adapter speaks tool turns and echoes thinking blocks

## Phase Goal

**As a** developer, **I want to** have an agent read a case's extracted invoice and validator findings through read-only MCP tools and return a typed approve, reject or escalate decision, graded like extraction, **so that** the project shows an agent taking action with tools under the same measured discipline (D-26).

This plan's slice: **As a** developer, **I want to** send an agent step to Claude with tools and a structured-output schema and read its tool calls back, **so that** the hand-written loop can run against the real model behind the same gateway as extraction.

<objective>
Map the plan 02 tool-turn records in AnthropicLlmGateway: request side (system prompt, tools, document-less first turn, assistant blocks echoed unchanged including thinking signatures, tool_result blocks) and response side (ordered blocks, tool_use stop reason), with strict validation before anything is sent. Proven offline against a recording handler.

Purpose: the provider half of AGT-02 and phase decision D-13 (structured output combined with tools), plus D-15 (a priced thinking model chosen by override can continue a tool conversation because its thinking blocks are echoed, D-37). The live probe (plan 07) exercises this mapping against the real API.
Output: AnthropicLlmGateway tool mapping, two synthetic response fixtures, adapter tests.
</objective>
