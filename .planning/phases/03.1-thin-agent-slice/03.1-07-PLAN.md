# Phase 3.1 Plan 07: spike first: does Haiku 4.5 take tools and a Decision schema in one request?

## Phase Goal

**As a** developer, **I want to** have an agent read a case's extracted invoice and validator findings through read-only MCP tools and return a typed approve, reject or escalate decision, graded like extraction, **so that** the project shows an agent taking action with tools under the same measured discipline (D-26).

This plan's slice: **As a** developer, **I want to** confirm against the live API, for about US$0.10, that tools and the Decision output schema combine on claude-haiku-4-5 and that the model reads before it decides, **so that** the agent loop is built on a verified final-answer path instead of an assumption.

<objective>
Add an `--agent-probe` mode to the LlmSpike tool that sends the exact agent conversation (agent-001 system prompt, the case user turn, the four tool definitions, the Decision model-facing schema as output_config.format, tool turns answered from the committed cases) through the real AnthropicLlmGateway, offline in dry-run and live under a US$0.10 budget; add the capped `just agent-probe` recipe; have a human run it; record the outcome as D-38.

Purpose: phase decision D-13 ("Spike first: confirm that tools and output_config.format combine on claude-haiku-4-5"), RESEARCH Open Question 1 and assumptions A1-A3; the loop in plan 08 implements the path D-38 records. Live paid calls happen only at the human checkpoint (user decision after research; AGENTS.md live-call rules).
Output: AgentProbe.cs, the agent-probe recipe, docs/spikes/03-agent-probe.md (written by the live run), D-38.
</objective>
