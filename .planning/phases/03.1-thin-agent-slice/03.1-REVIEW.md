### WR-01: Unmapped exception types from the MCP client escape as HTTP 500 instead of a recorded tool failure

**File:** `dotnet/src/Carimbo.Agent/AgentToolbox.cs:437-445` (used at `:416-430` and `:477`)
**Issue:** D-35 says a tool failure ("MCP error result, unknown tool, transport failure or timeout, while listing, during the loop or in the guard") ends the run with the code decision escalate / `tool_failed`. `McpAgentToolbox.Map` only maps `AgentToolException`, caller-vs-timeout cancellation, `McpException`, `HttpRequestException` and `IOException`; every other exception returns null and is rethrown (`throw;` at line 426, or the `when` filter at line 477 not matching). Anything else the SDK or HttpClient can surface (for example a `JsonException` from a malformed JSON-RPC body, an `InvalidOperationException` or `ObjectDisposedException` from a closed session, an `AuthenticationException` that is not wrapped) is not caught anywhere in `AgentRunner` (`RunToolCoreAsync` catches only `AgentToolException` and timeouts; `DecideCoreAsync` catches only `AgentToolException` around `ConnectAsync`). It propagates through `DecideAsync` to the endpoint, which has no handler, so the eval run becomes a 500 and a harness error rather than a graded escalation, and the span only gets `error.type`. I could not exercise the SDK against a hostile host here, so which concrete types occur is unverified; the gap is structural.
**Fix:** Treat every non-cancellation failure of the toolbox as a tool failure by making the fallback arm of `Map` a transport/protocol error instead of null:
```csharp
internal static AgentToolException? Map(Exception exception, CancellationToken caller, string action) => exception switch
{
    AgentToolException known => known,
    OperationCanceledException when caller.IsCancellationRequested => null,
    OperationCanceledException => new AgentToolException("timeout", $"The Tools host did not finish {action} in time."),
    McpException => new AgentToolException("protocol_error", $"The Tools host answered with a protocol error while {action}."),
    HttpRequestException or IOException => new AgentToolException("transport_error", $"The Tools host could not be reached while {action}."),
    JsonException or InvalidOperationException or ObjectDisposedException =>
        new AgentToolException("protocol_error", $"The Tools host answered unusably while {action}."),
    _ => null,
};
```
Keep `null` (rethrow) only for genuine programming errors you want to surface, and add a test for each added type.

### WR-02: Stop reasons other than end_turn, max_tokens and refusal are parsed as a final answer

**File:** `dotnet/src/Carimbo.Agent/AgentRunner.cs:178-209`
**Issue:** After the `tool_use` branch, only `Refusal` and `MaxTokens` get a typed failure. `StopSequence` and `Other` (the gateway maps every unknown provider stop reason to `Other`, `AnthropicLlmGateway.cs:453-461`, which includes `pause_turn` and `model_context_window_exceeded`) fall through to `Parse(response.Text)`. A context-window stop with a half-written JSON is then reported as `schema_invalid` with a JSON-path message instead of `truncated`, which mixes two failure classes the eval is meant to count apart (D-35, EXT-02, EVAL-04). A `pause_turn` answer whose partial text happens to be a valid Decision would be accepted as the final answer. The step has already been recorded and billed either way.
**Fix:** Make the allowed set explicit and type everything else:
```csharp
switch (response.StopReason)
{
    case LlmStopReason.EndTurn:
        break;
    case LlmStopReason.Refusal: /* existing */
    case LlmStopReason.MaxTokens: /* existing */
    default:
        return Typed(
            AgentStatus.Truncated, // or a dedicated failure kind
            new AgentFailure("unexpected_stop", null, null, "The model stopped for a reason the agent does not accept."),
            TextOrNull(response.Text), steps, model, toolsSha256);
}
```
Pick the status deliberately (D-35 lists the allowed statuses; if none fits, record the choice in a decision entry).

### WR-03: The default agent model is never checked against the pricing table

**File:** `dotnet/src/Carimbo.Api/Program.cs:73-96` (override check at `dotnet/src/Carimbo.Api/EvalEndpoint.cs` `CheckModel`)
**Issue:** The `overrides.model` path refuses any model the pricing table cannot price, with the stated reason (T-03-21, T-03-23) that an unpriced model "would spend with a null cost and slip past the runner's cost cap". `Agent:Model` is bound from configuration with only `MaxSteps`, `MaxTokens`, `ToolCallTimeoutSeconds` and `ToolsUrl` validated. var pricingTable = LlmPricingTable.LoadEmbedded();

### WR-04: Case tool arguments are not bound to the case under decision

**File:** `dotnet/src/Carimbo.Agent/AgentRunner.cs:157` (call), `:305-350` (`RunToolCoreAsync`)
**Issue:** The first user turn names one case, and the guard always reads that case's status (`:212-219`), but model-initiated calls forward whatever `case_id` the model put in the arguments. A model that fetches `get_invoice` / `get_validator_findings` for a different, valid case (hallucination, or a prompt-injection string inside an earlier tool result, which the prompt only asks it to ignore) decides on the wrong data while the guard checks the right status; the run is recorded as an ordinary `ok` tool call, and the grader's `citations_valid` (source is a tool the model called) cannot tell. The run's `caseId` needs to be passed to `RunToolAsync`; it is already available in `RunAsync`.

### WR-07: ScriptedHost diverges from the real gateway in ways that weaken the e2e

**File:** `dotnet/tests/Carimbo.ScriptedHost/Program.cs:54-72, 134-180`
**Issue:** The e2e (`python/tests/test_e2e_decisions.py`) runs the real composition with this gateway standing in for `AnthropicLlmGateway`. Compared with the real gateway (`AnthropicLlmGateway.Map`, `AnthropicLlmGateway.cs:431-476`):
1. A final text answer yields `Blocks = []` here (`BlocksOf` returns early unless `thinking` or `tool_calls` is present), whereas the real gateway always adds a `Text` block. Cache entries (`llm-cache-entry-2` stores `blocks`) and any consumer of `Blocks` therefore differ between the scripted e2e and a live run, and the e2e cannot catch a bug that depends on the text block.
2. `ProviderMessageId` is always `null` here, so `provider_message_id` in the e2e response is never exercised.
3. A step that omits `stop_reason` maps to `LlmStopReason.Other` and then fails as `schema_invalid` with an unrelated message (the doc comment does not say a step needs `stop_reason`). A script with `tool_calls` and no `stop_reason` is a trap.
4. The real gateway rejects malformed tool conversations before sending (`ArgumentException`, 19 shapes pinned in `AnthropicGatewayTests`). The scripted gateway accepts any follow-up history, so the e2e proves nothing about the agent sending a well-formed history. It also never checks `request.Tools`, `SystemPrompt` or `OutputSchemaJson`. The unit tests cover those, but the e2e's claim of exercising "the real pipeline" is weaker than the doc comment suggests.
5. Failures are thrown synchronously from `CompleteAsync` (a non-async method) rather than as faulted tasks. This is how the Phase 3 extraction path already behaved, and the decorators are async, so it is harmless today, but a decorator that does not `await` inside a `try` would behave differently from the real gateway.
**Fix:** Make the scripted answer shape the real one: always emit a `Text` block when `text` is non-empty (drop the early return), set `ProviderMessageId` to a deterministic value such as `"msg_scripted_" + stepIndex`, default `stop_reason` to `end_turn` when there are no `tool_calls` and to `tool_use` when there are, and fail fast on `tool_calls` plus a non-`tool_use` stop reason. Optionally reuse the gateway's conversation validation (or assert in the host that follow-ups pair `tool_use` ids with `tool_result` ids) so the e2e checks the history.

### WR-08: A "decided" case with a missing or empty decision silently leaves the accuracy denominators

**File:** `python/src/carimbo_evals/decision_grader.py:195-203`
**Issue:** `decision = _dict(outcome.get("decision"))` returns `{}` for a null, absent or non-dict decision, and `if decision:` treats `{}` as falsy. A response with `outcome.status == "decided"` but no usable `decision` (a contract violation by the endpoint, or a regression in the agent loop) leaves `decision_correct` as `None`. It is therefore excluded from `accuracy.n`, from the escalation precision/recall `decided` set, and from `decision_schema` (`present` is empty), while still being counted as `decided` in `counts`. The headline accuracy then rises or stays flat while a broken run goes unnoticed. This is the same "typed failures never enter a denominator" rule, applied to something that is not a typed failure. `test_decision_models.py` validates the golden fixtures but nothing pins this grader path.
**Fix:** Treat `status == "decided"` without a decision object as incorrect and flag it:
```python
decision = outcome.get("decision")
if not isinstance(decision, dict) or not decision:
    graded["decision_correct"] = False
    graded["decision_schema_valid"] = False
    return graded  # decided with no decision: a contract violation, graded wrong
```
Add a grader test for `status: "decided"` with `decision: null`.

### IN-02: `Truncate` can split a surrogate pair

**File:** `dotnet/src/Carimbo.Agent/AgentToolbox.cs:519-520`
**Issue:** `text[..MaxErrorLength]` cuts at a UTF-16 code-unit boundary. If the 300th char is a high surrogate, the kept string ends in a lone surrogate, and `System.Text.Json` throws when it later writes the tool-error message into the endpoint response (the response record carries `ErrorMessage`). Extremely unlikely with the host's current ASCII messages, but the helper is the control for hostile or accidental long host text, and an untested one (known residual).
**Fix:**
```csharp
private static string Truncate(string text)
{
    if (text.Length <= MaxErrorLength) return text;
    var end = char.IsHighSurrogate(text[MaxErrorLength - 1]) ? MaxErrorLength - 1 : MaxErrorLength;
    return text[..end];
}
```
