## Fixed Issues

### WR-01: Unmapped exception types from the MCP client escape as HTTP 500 instead of a recorded tool failure

**Files modified:** `dotnet/src/Carimbo.Agent/AgentToolbox.cs`, `dotnet/tests/Carimbo.Agent.Tests/AgentTerminalStateTests.cs`
**Commit:** d7dfe48
**Applied fix:** `McpAgentToolbox.Map` now maps `JsonException` and `InvalidOperationException` (which includes `ObjectDisposedException`) to `protocol_error`, so they end the run as escalate / `tool_failed`. Other exception types still rethrow (programming errors). Test: a handler that throws each of the three types ends in a `protocol_error` tool failure with no model call; the same test fails on the old code (3 failures). Note: the review's line numbers did not match the file (188 lines); the content did.
**Status:** fixed: requires human verification (error-mapping policy; a reviewer should confirm that treating `InvalidOperationException` as a protocol error is the wanted breadth).

### WR-02: Stop reasons other than end_turn, max_tokens and refusal are parsed as a final answer

**Files modified:** `dotnet/src/Carimbo.Agent/AgentRunner.cs`, `dotnet/tests/Carimbo.Agent.Tests/AgentTerminalStateTests.cs`, `docs/DECISIONS.md`, `justfile`
**Commit:** 04d446c
**Applied fix:** Only `end_turn` reaches the parser. `stop_sequence` and `Other` (pause_turn, context-window stop) end the run as status `truncated` with failure kind `unexpected_stop`, partial text kept as `raw_output`, never parsed, no guard call. No new status was added, so the typed-failure vocabulary of D-35 is unchanged; the choice is recorded as the new D-39 (and `docs-check` now requires the D-39 heading). Tests: a valid decision under each stop reason is still `truncated`.
**Status:** fixed: requires human verification (the choice of `truncated` over `schema_invalid` for unaccepted stop reasons is a judgement call, recorded in D-39).

### WR-03: The default agent model is never checked against the pricing table

**Files modified:** `dotnet/src/Carimbo.Api/Program.cs`, `dotnet/tests/Carimbo.Api.Tests/DecisionEndpointTests.cs`, `docs/DECISIONS.md`
**Commit:** dec10a3
**Applied fix:** The pricing table is loaded once, before the other `Agent` checks, and startup fails with `Agent:Model must be a model id the pricing table can price` for an empty or unpriced id. Tests: startup fails for `""`, whitespace and an unknown id; a priced non-default model starts. The existing test `An_unpriced_model_makes_the_cost_and_the_incurred_cost_unknown_with_a_warning` configured an unpriced `Agent:Model`, which is now (correctly) unreachable; it was replaced by a comment pointing at the startup tests. The unknown-cost rendering stays pinned by the Llm gateway tests and the extraction goldens.

### WR-04: Case tool arguments are not bound to the case under decision

**Files modified:** `dotnet/src/Carimbo.Agent/AgentRunner.cs`, `dotnet/tests/Carimbo.Agent.Tests/AgentTerminalStateTests.cs`, `docs/DECISIONS.md`
**Commit:** 9a48c14
**Applied fix:** The runner passes the run's case id to `RunToolAsync`; a model-initiated call to `get_extraction_status`, `get_invoice` or `get_validator_findings` whose `case_id` is missing, not a string, not exactly the run's case, or in unparseable arguments is a tool failure `invalid_arguments` ("The case_id argument is not the case under review."), ends in escalate / `tool_failed`, and is never sent to the host. The guard call (built by code) and `get_policy` are not checked. Tool definitions and schemas are byte-identical, so no cache key moves. Tests: 9 theory rows (other case, wrong case, missing, wrong type, null, array, malformed) assert the host is never called and the other case id does not appear in the message; a positive test pins the four correct calls plus the guard. Two existing tests that used `dc-999` as an error source now run `dc-999` as the run's own case. Recorded in D-39.
**Status:** fixed: requires human verification (behavioural rule on model tool calls).

### WR-05: `A_cache_mode_override_is_accepted_on_a_host_that_has_a_cache...` cannot fail for the reason it claims

**Files modified:** `dotnet/tests/Carimbo.Api.Tests/DecisionEndpointTests.cs`

### WR-06: Failure-handling branches of `McpAgentToolbox` and the tool-failure reason redaction are untested

**Files modified:** `dotnet/tests/Carimbo.Agent.Tests/AgentToolboxFaultTests.cs` (new)
**Commit:** 5243595

The `ConnectAsync` timeout and the `protocol_error` mapping of `McpException` are not separately exercised (the latter is partly covered by WR-01's tests). Passed three runs in a row (no flakiness seen).
