# Phase 3.1 Plan 05: the Python harness runs and grades decision cases

## Phase Goal

**As a** developer, **I want to** have an agent read a case's extracted invoice and validator findings through read-only MCP tools and return a typed approve, reject or escalate decision, graded like extraction, **so that** the project shows an agent taking action with tools under the same measured discipline (D-26).

This plan's slice: **As a** developer, **I want to** run the decision cases through the eval endpoint with the existing runner and grade the stored records offline, **so that** decision accuracy is measured with the same cost cap, resume and replay discipline as extraction.

<objective>
Generalise run_cases with a RunSpec (endpoint path, record version, payload builder, timeout) so extraction behaviour is unchanged and decisions reuse cap, resume and accounting; add the `decisions` and `grade-decisions` commands, strict decision-1 contract models, a deterministic decision grader and a summary. Proven first as one case through run, record and grade.

Purpose: AGT-04 (the harness runs the cases through the eval endpoint and grades offline and deterministically, records carry tool calls, steps, tokens, cost and trace id) and the runner half of AGT-06 (cap and free replay accounting), per phase decisions D-17 and D-19, D-36 and RESEARCH Open Question 6 (generalise run_cases). The endpoint itself is plan 09; this plan works against the decision-1 contract recorded in D-36 with a mock transport.
Output: runner generalisation, CLI commands, decision_contract.py, decision_grader.py, decision_summary.py, tests.
</objective>
