# Phase 3.1 Plan 09: POST /eval/decisions returns and records the agent's decision

## Phase Goal

**As a** developer, **I want to** have an agent read a case's extracted invoice and validator findings through read-only MCP tools and return a typed approve, reject or escalate decision, graded like extraction, **so that** the project shows an agent taking action with tools under the same measured discipline (D-26).

This plan's slice: **As a** developer, **I want to** post a case id to the eval endpoint and get back the decision with every step, tool call, token, cost and the trace id, **so that** the Python harness can run and grade decision cases over real HTTP like extraction.

<objective>
Serve contract decision-1 at POST /eval/decisions from the Api, composed with the agent over the existing gateway decorator stack, with the gating, auth and validation of /eval/extractions, bounded Agent configuration, a shared incurred-cost rule, and agent and tool spans on the request trace. Proven first with one case over TestServer and an in-process Tools host.

Purpose: AGT-04 (the endpoint the harness calls; each record carries tool calls, steps, tokens, cost and trace id) and the "returned and recorded, nothing executes it" half of AGT-03, per phase decisions D-12, D-15, D-16, D-36 and RESEARCH Pattern 7 and Pattern 8 (D-31 tracing).
Output: DecisionEndpoint, Program registration, AgentTelemetry, Api tests.
</objective>
