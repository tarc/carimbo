# Phase 03.1 Plan 04: the Anthropic adapter speaks tool turns and echoes thinking blocks Summary

**AnthropicLlmGateway now carries a full agent conversation against the real SDK types: document-less steps with a system prompt, tools and the decision output schema, assistant blocks (thinking signatures, redacted thinking, text, tool_use) echoed unchanged, tool_result turns, ordered response blocks with a tool_use stop reason, and strict pre-send validation that never lets a malformed tool conversation reach the wire.**

## Performance

- **Completed:** 2026-10-22T00:36:00Z
- **Tasks:** 2
- **Files modified:** 4 (2 created, 2 modified)

## Accomplishments

- BuildParameters handles a null document (prompt-only first turn; a non-null document must still be application/pdf), maps SystemPrompt and Tools only when present (left unset otherwise, so the extraction body is unchanged), and maps assistant Blocks and user ToolResults to the SDK block params. The first compile used the SDK types as the plan predicted (the system prompt takes a plain string; A-04-1 compiler half is confirmed).
- Map walks the provider content in order into LlmResponse.Blocks and maps stop reason tool_use; Text stays the concatenation of the text blocks. A thinking answer echoed back sends the identical signature and redacted data.
- ValidateTools and ValidateToolTurns refuse, before any HTTP request: tool schema members beyond type, properties and required, non-object or non-"object"-typed schemas, invalid JSON, duplicate tool names, unsendable assistant blocks, results that do not answer the preceding tool_use ids exactly and in order (different, missing, extra, reordered, or on a turn with no tool_use), role misuse, and non-object tool_use inputs.

## Decisions Made

- The schema validator requires `type` to be present and equal to "object" (the plan lists "type is not object"; a missing type is treated the same, since the API requires it).
- A user turn that follows a tool_use turn without results is refused, as is a results turn after a turn without tool_use; plain text turns after plain text turns are untouched, so extraction repair conversations behave as before.
