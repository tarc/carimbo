**A typed Decision (evidence citations, reason, outcome, required cause enum) now flows from the C# Domain through the same Wire.Options, schema export, model-facing projection and datamodel-codegen chain as Invoice, with the Invoice artifacts untouched byte for byte.**

## Accomplishments

- Decision.cs holds DecisionOutcome, the new DecisionCause (none, extraction_not_success, policy_warning, over_limit, tool_failed, step_budget_exhausted), EvidenceItem and Decision, with Description attributes that feed the schema. Property order puts evidence and reason before the verdict because structured output is generated in schema order.
- CanonicalSchema.Export(Type) and ExportJson(Type) carry the existing body; Export() and ExportJson() delegate with typeof(Invoice), so schema/invoice.schema.json, schema/invoice.model.schema.json and generated.py did not change.
- ModelFacingSchema.Json(Type) is the single project, budget-check, serialize composition for any exported root; the decision model schema has 0 optional and 0 union properties.
- SchemaExport writes and --check verifies both decision schema files; `just schema` runs a second codegen (`codegen_decision`) writing decision_generated.py.
- Decision.NullViolations() covers the hole where System.Text.Json accepts a null collection element (`evidence[0]`), via a reflection walker now shared with Invoice.

## Issues Encountered

- A sibling expectation in the plan, "a decision with `\"reason\": null` deserializes", does not hold: Wire.Options (RespectNullableAnnotations) rejects a null non-nullable member with JsonException.
