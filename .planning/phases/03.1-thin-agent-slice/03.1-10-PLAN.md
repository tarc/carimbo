# Phase 3.1 Plan 10: the decision cases run end to end in `just check`, and the contract is pinned by golden fixtures

## Phase Goal

**As a** developer, **I want to** have an agent read a case's extracted invoice and validator findings through read-only MCP tools and return a typed approve, reject or escalate decision, graded like extraction, **so that** the project shows an agent taking action with tools under the same measured discipline (D-26).

This plan's slice: **As a** developer, **I want to** run every decision case, every escalation cause and a free replay over real HTTP and real MCP with no provider key, **so that** `just check` proves the whole agent slice on every change.

<objective>
Teach the ScriptedHost to script agent steps (tool_use turns and final answers keyed by case id), add a two-process e2e (Tools host plus ScriptedHost Api) driven through the documented `carimbo-evals decisions` and `grade-decisions` commands covering every decision, every escalation cause, a typed failure and a read_only replay, and pin decision-1 with golden fixtures parsed by the strict Python models.

Purpose: AGT-05 (offline tests drive the loop and the decision cases end to end against the fake model, cover each decision and each escalation cause, and run in `just check`), the cross-stack contract half of AGT-04, and the offline half of AGT-06, per phase decisions D-18, D-19 and D-36 (golden fixtures, Claude's discretion: yes, mirroring D-32).
Output: ScriptedHost agent scripting, test_e2e_decisions.py, DecisionGoldenResponseTests and data/contract/decision-responses, decision-request.json, test_decision_contract.py, `just golden` extended.
</objective>
