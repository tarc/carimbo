## Pattern Assignments

### `LlmContracts.cs` (seam growth)

**Analog:** itself, lines 29-68. Today `LlmRequest(Model, MaxTokens, Prompt, Document, OutputSchemaJson)` has `Document` and `OutputSchemaJson` as required positional parameters, and `FollowUps` are text-only `LlmTurn(Role, Text)`. Extend with init properties in the same style (XML doc plus "Part of the response-cache key; the provider never sees it"):
```csharp
public sealed record LlmRequest(string Model, int MaxTokens, string Prompt, LlmDocument Document, string OutputSchemaJson)
{
    public IReadOnlyList<LlmTurn> FollowUps { get; init; } = [];
    public bool CacheDocument { get; init; }
    public string? PromptVersion { get; init; }
    public string? ReplicateSalt { get; init; }
    public LlmCacheMode? CacheMode { get; init; }   // excluded from the key
}
```
Make `Document` nullable (agent has no PDF). Add `Tools` (definitions), and tool_use / tool_result turn shapes beside `LlmTurn`. `LlmResponse` (lines 158-174) needs tool-call output and a `LlmStopReason.ToolUse` member (enum lines 135-142 has none). Keep `Cost`/`Cache` set by decorators. Provider types never cross the seam.

### `LlmCacheKey.cs`

**Analog:** itself, lines 18-75. Hand-written canonical JSON, member by member; large inputs enter as SHA-256. Rules to keep:
- Bump `Version` (line 18, `llm-cache-key-1`) to `-2` when adding tool definitions and tool turns. Old entries stop matching visibly.
- Add every new `LlmRequest` property to `KeyedProperties` (lines 21-33) or `ExcludedProperties` (line 39). The reflection test in `CacheKeyTests.cs` forces this and pins `PinnedCanonicalJson`/`PinnedKey` (lines 14-27), so the pin must be recomputed outside the code under test and bumped deliberately.
- Null Document needs a defined canonical form (line 58-59 dereference it today).
- Cache stores only `end_turn` answers (`CachingLlmGateway`, `LlmCacheStore`). The planner must decide how `tool_use` turns replay; otherwise `read_only` replay misses on intermediate steps.

### `TracingLlmGateway.cs` and `LlmTelemetry.cs`

**Analog:** `TracingLlmGateway.cs` lines 15-60. One `chat <model>` client span per call from `LlmTelemetry.Source`; tags only from `LlmTelemetry.AllowedTags`; no content; `catch (LlmGatewayException)` calls `Fail(activity, Snake(kind))`.
```csharp
using var activity = LlmTelemetry.Source.StartActivity("chat " + request.Model, ActivityKind.Client);
if (activity is null) return await inner.CompleteAsync(request, cancellationToken).ConfigureAwait(false);
activity.SetTag(LlmTelemetry.PromptVersion, promptVersion);
```
Copy for the agent root span (per case) and per tool-call child spans (name plus outcome tags, no arguments or values). Add new tag names to `AllowedTags` so the allow-list test stays green.

### `Decision.cs` (Domain record) and schema chain

**Analog:** `dotnet/src/Carimbo.Domain/Invoice.cs` (records, snake_case, string enums, `Money` via `MoneyJsonConverter` in `Wire.cs`), `CanonicalSchema.cs` (`ExportJson()`), `Wire.cs` (single `Wire.Options`). Domain stays dependency-free. Respect the structured-output limits (<=24 optional, <=16 union properties, no `oneOf`, no `minimum/maxLength`). `evidence` is `{source, ref, value}` (D-14); `guard`/`cause` live in the response, not necessarily the model-facing schema. Avoid `JsonSerializerDefaults.Web`.

**SchemaExport** (`dotnet/tools/SchemaExport/Program.cs` lines 23-27): add rows to the `outputs` array:
```csharp
var outputs = new (string RelativePath, string Text)[]
{
    ("schema/invoice.schema.json", CanonicalSchema.ExportJson()),
    ("schema/invoice.model.schema.json", ExtractionContract.Default.OutputSchemaJson),
};
```
`--check` compares bytes, UTF-8 no BOM, LF. Note the `justfile` `codegen` variable takes a single `--input schema/invoice.schema.json` and writes one `generated.py`; a second schema needs a second codegen invocation or a combined input (planner decision; both must keep `--disable-timestamp` and the identical input path string). `schema-check` is `git diff --exit-code -- schema python/src/carimbo_models`.

### `DecisionEndpoint.cs` (`POST /eval/decisions`)

**Analog:** `dotnet/src/Carimbo.Api/EvalEndpoint.cs`. Copy the following verbatim in spirit:

**Gating and TryMap** (lines 39-74): Development/Eval only, `CARIMBO_EVAL_API_KEY` configured, `ILlmGateway` registered; logs unmet conditions, never values. Hash the key once:
```csharp
var expectedKeyHash = SHA256.HashData(Encoding.UTF8.GetBytes(evalKey!));
Func<HttpContext, Task<IResult>> handler = context => HandleAsync(context, expectedKeyHash);
app.MapPost(Route, handler).WithMetadata(new RequestSizeLimitAttribute(MaxBodyBytes));
```
**Auth before binding** (lines 76-102): `X-Api-Key` header, `CryptographicOperations.FixedTimeEquals`, 401 before reading the body, 415 for non-JSON, 413 via `ContentLength`.

**Binding and 400s** (lines 104-130): `ReadFromJsonAsync<EvalRequest>(jsonOptions, ...)` with `JsonException` mapped to `Invalid("body", ...)`; `ContractVersion` must equal the constant (use `"decision-1"`-style as D-16 says).

**Overrides as raw `JsonElement`** (lines 155-250): `cache_mode` (`LlmCacheModes.TryParse`; Off only when no cache settings), `replicate_salt` (`IsValidSalt` allow-list), `model` (`pricing.CanPrice`, never echo the value), `prompt_version` (catalog allow-list). Each reported as `Invalid("overrides.<field>", ...)`.
```csharp
private static IResult Invalid(string field, string problem) =>
    Results.ValidationProblem(new Dictionary<string, string[]> { [field] = [problem] });
```
**Trace id** (lines 255-266): reuse the `Activity.Current is null` owned-activity block so the response always has `trace_id`. Typed failures are HTTP 200 (see `EvalResponse.From`). `case_id` validation: add a strict allow-list (it keys a disk lookup in the Tools host; never allow path separators).

Request records: `EvalRequest(ContractVersion, CaseId, ..., JsonElement? ..., EvalOverrides? Overrides)` pattern at lines ~290-310; `HttpJsonOptions` are configured in `Program.cs` lines 46-52 (snake_case, `Disallow` unmapped members, `RespectRequiredConstructorParameters`).

## Shared Patterns

### Gateway decorator stack
**Source:** `Program.cs` lines 239-267. Tracing outermost, Caching, CostAccounting, SDK adapter. Apply to every agent model call; do not add retry layers (D-28).

### Bounded config, validated at startup and at the endpoint
**Source:** `Program.cs` lines 58-62 and `ExtractionSettings.MaxRepairsLimit`. Apply to `Agent:MaxSteps` (no per-request override per D-12).

### Eval endpoint hygiene
**Source:** `EvalEndpoint.cs` lines 76-250. Auth before binding, `ValidationProblem` keyed by field, never echo submitted values, typed failures as HTTP 200, trace id always present.

### No content in telemetry
**Source:** `TracingLlmGateway.cs` (class remarks) and `LlmTelemetry.AllowedTags`. Tool arguments and results never reach span tags.

### Generated artifacts with a staleness gate
**Source:** `SchemaExport --check`, `just schema-check`, `just datagen-check`, `just golden`. Applies to the Decision schema, Pydantic models, `data/decision/*` and any golden fixtures. Never hand-edit.

### Hermetic tests
Turn the response cache off explicitly or use a per-test directory (see `CacheConfigurationTests.cs`, `EvalEndpointTests.cs`).
