# Phase 3.1 Plan 06: a stateless MCP Tools host serves the cases read-only

## Phase Goal

**As a** developer, **I want to** have an agent read a case's extracted invoice and validator findings through read-only MCP tools and return a typed approve, reject or escalate decision, graded like extraction, **so that** the project shows an agent taking action with tools under the same measured discipline (D-26).

This plan's slice: **As a** developer, **I want to** list and call four read-only case tools from a real MCP client over Streamable HTTP, **so that** the agent's data boundary is a genuine MCP server that can never change state.

<objective>
Create Carimbo.Tools: a separate ASP.NET Core host using ModelContextProtocol.AspNetCore 2.2.0 (stateless Streamable HTTP at /mcp, loopback by default, AllowedHosts restricted) whose four tools read the committed decision cases through CaseStore and return CaseToolCatalog's renderings. Prove it end to end with an McpClient listing and calling each tool, then harden read-only, path safety, statelessness and host filtering.

Purpose: AGT-01 entirely (separate Tools host, stateless MCP over Streamable HTTP, tools read a case's invoice and findings, no tool changes state, a test lists and calls each), per phase decisions D-02, D-03 and D-35, RESEARCH Pattern 1 and the security domain (V4, V5, V12, V14).
Output: Carimbo.Tools, Carimbo.Tools.Tests, the two MCP package pins.
</objective>
