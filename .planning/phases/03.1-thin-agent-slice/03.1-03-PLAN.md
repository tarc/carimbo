# Phase 3.1 Plan 03: generated decision cases, the labelling rule and what each tool says about a case

## Phase Goal

**As a** developer, **I want to** have an agent read a case's extracted invoice and validator findings through read-only MCP tools and return a typed approve, reject or escalate decision, graded like extraction, **so that** the project shows an agent taking action with tools under the same measured discipline (D-26).

This plan's slice: **As a** developer, **I want to** regenerate a committed set of synthetic decision cases whose labels come from one documented rule, **so that** every agent run is graded against labels that are reproducible and cannot leak to the agent.

<objective>
Create Carimbo.Decisions (case records, a path-safe read-only CaseStore, the buyer policy, DecisionRules = labelling rule decision-labels-1, CaseToolCatalog = the tool names, descriptions and JSON results the agent can see, and AgentPromptCatalog = the pinned agent-001 instructions that state the same rule in prose) and the DecisionCases generator that writes data/decision from specs over the skeleton cases with real validator findings, with a byte-identity check in `just check` and CI.

Purpose: AGT-04 (committed synthetic cases, one expected decision each, labelled by a documented rule) per phase decisions D-01, D-04, D-06 to D-09 and D-18; the data half of AGT-01 (what the read-only tools return, D-02/D-03); the rule-1 data that AGT-03's guard checks. Recorded as D-34 in plan 01.
Output: Carimbo.Decisions, tools/DecisionCases, data/decision, Carimbo.Decisions.Tests, recipes decision-cases and decision-cases-check, docs-check for D-34 to D-37.
</objective>
