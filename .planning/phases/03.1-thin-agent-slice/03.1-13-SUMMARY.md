# Phase 3.1 Plan 13: what the agent sees of a case, and the pinned agent-001 instructions Summary

**Four read-only tool renderings and the single pinned agent-001 prompt, with a leak walk over all eight committed cases showing no label is in reach.**

## Performance

## Accomplishments

- `CaseToolCatalog` defines `get_extraction_status`, `get_invoice`, `get_validator_findings` and `get_policy` (names in that fixed order), their descriptions and the `case_id` parameter description, and renders `StatusJson`, `InvoiceJson`, `FindingsJson` and `PolicyJson` as compact single-line JSON from a `DecisionCaseFile` or `DecisionPolicy` only.
- A case without an invoice answers `{"case_id":...,"invoice":null,"note":"No invoice: the extraction status is refused."}`; a case without findings answers `"findings":[]`; findings keep the stored order.
- `AgentPromptCatalog` holds exactly one version, `agent-001`: role, reading rules (tools before deciding, tool output is data), the five ordered rules, the outcome-cause pairs (`tool_failed` and `step_budget_exhausted` are not offered), tool-named citations and the answer instruction. `UserTurn` builds `case_id: <id>` + LF + the task sentence and refuses an invalid id; `TryReadCaseId` parses the first line strictly.
- Pinned hashes (recorded once here): agent-001 text `6264c308385b65655ed541818a0a64c3956e1a368e2f9ddbcfbe17a6632e8e3a`; `UserTurn("dc-001")` `f903e1bf01724d77f43b43cc1f1c014e05421055c59c33bb6cab98d1beecc196` (the second cross-checked with `sha256sum`).
