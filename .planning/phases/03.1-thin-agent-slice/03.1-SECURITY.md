## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Model output → Wire.Options parse / loop control | The Decision JSON, tool names and tool inputs come from the model and are untrusted until they parse strictly | Model-generated JSON |
| Committed schema → Python models | Generated code is trusted only because it is regenerated and compared | Generated source |
| Cache directory on disk → CachingLlmGateway | Entry files, now with tool calls and thinking signatures, are replayed as model answers | Stored model answers (synthetic data) |
| Request content → cache key | Tool definitions, tool results and the system prompt feed the key | SHA-256 digests of request content |
| case_id (from a request or from the model) → CaseStore file path | An untrusted identifier selects a file on disk | Case identifier |
| data/decision → agent-visible tool results | Anything rendered from a served case file is visible to the model under test | Synthetic case data; labels must never cross |
| Gateway → Anthropic Messages API | Tool definitions, tool results (case data) and echoed model blocks leave the process | Synthetic case data, prompts |
| Provider response → LlmResponse | Tool names, ids and inputs come from the model | Model-generated blocks |
| Runner → eval endpoint | The eval key travels in a header; responses are untrusted JSON | Eval key (secret), decision responses |
| Stored run files → grader | cases.jsonl may be torn or edited | Run records |
| Loopback client → MCP endpoint /mcp | Unauthenticated JSON-RPC over HTTP; case ids originate from the model | Tool calls and case renderings |
| Tools host → data/decision on disk | Read-only file access selected by case id | Case files, policy |
| Developer shell → Anthropic API (`just agent-probe`, `just decisions`) | Paid calls with the provider key | Provider key (secret), spend |
| Probe output and run output → git | The spike doc and copied run directories become committed evidence | Measured results |
| Tool results (case data) → next model request | Synthetic but untrusted strings re-enter the prompt | Case data (prompt-injection surface) |
| Agent / Api → Tools host | Loopback MCP; the URL comes from configuration | Tool calls |
| HTTP client → /eval/decisions | Untrusted body and headers; the static key gates access | Requests, eval key |
| Api → trace exporter | Span attributes leave the process when OTLP is configured | Allowlisted span tags only |
| Test processes on loopback ports | Two local hosts started by pytest with an ephemeral eval key | Ephemeral eval key |
| Golden fixtures → git | Generated responses become committed contract files | Generated responses |
| Local hosts on 127.0.0.1:5080 and :5090 | The Api and the Tools host started by the recipe | Local HTTP traffic |
| Decision records → implementing plans; docs/ → git | D-34..D-37 are the contract; docs become committed history | Documentation |
| Pinned prompt and tool descriptions → every agent request | Their bytes are cache-key inputs and live-evidence inputs | Prompt and tool text |

### Residual notes (non-blocking, candidates for a later fix)

1. **T-03.1-29:** the 300-character truncation of tool error text exists (AgentToolbox.cs) but no test pins it. Our own Tools host returns only short fixed messages, so the residual risk is nil today.
2. **T-03.1-22:** the probe adds `cost ?? 0m` to its spend and adds nothing for a call that failed after the request was sent (e.g. a timeout), so its budget can undercount such calls. Bounded by MaxRetries 0, the pre-flight estimate before every call and both probe models being priced.
3. **T-03.1-18:** the default AllowedHosts applies only when the setting is empty; an operator who sets `AllowedHosts=*` turns host filtering off. The loopback bind still holds; whether the MCP SDK validates `Origin` is unverified (A6).
4. **T-03.1-33:** `localhost` is accepted by name, so its resolution depends on the machine's hosts file. Acceptable for a dev and eval host.
