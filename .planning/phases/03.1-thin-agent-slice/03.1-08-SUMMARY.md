# Phase 3.1 Plan 08: the hand-written agent loop decides a case over MCP Summary

**Carimbo.Agent: a framework-free tool-use loop over a per-run MCP client that decides committed cases, escalates by code on budget exhaustion, tool failure and a non-success extraction, and keeps model failures as typed failures; proven on dc-001 against the real Tools host with a free cached replay.**

## Performance

- **Duration:** 12 min (2026-10-22T02:59:43Z to 03:11:18Z for the code; SUMMARY and state follow)
- **Tasks:** 3 (1 tracer, 2 auto, all TDD)
- **Files:** 13 changed (11 created, 2 modified)
- **Tests:** 51 in Carimbo.Agent.Tests; `just dotnet-check` 1157 passed, 0 failed

## Accomplishments

- **Tracer (Task 1).** `AgentRunner` decides dc-001 `approve` in two model steps: step 0 asks for the four tools, they run over a real MCP boundary (in-process Tools host) in block order, the next request echoes the assistant blocks and returns all four results in one user turn, step 1 is the Decision. The guard then makes its own recorded `get_extraction_status` call (source `guard`, not a step, not in any step's tool calls). A second runner in `read_only` over the same cache directory makes zero model calls and returns the same decision, guard and tool calls with `http_attempts` 0 and cache status hit on both steps. Request overrides (model, cache mode, replicate salt) reach every request. The four listed tool schemas pass a real `AnthropicLlmGateway` unchanged (recording handler, no network).
- **Failures made by code (Task 2).** A tool error result, an unlisted tool name, a transport or protocol fault, a timeout, an unreachable Tools host and a Tools host that lists a non-read-only tool each end at once in escalate / `tool_failed` with the tool, source (`model`, `guard` or `list`) and error kind recorded and no further model call; the remaining calls of that answer are recorded `skipped`. A `tool_use` answer on step `MaxSteps` ends in escalate / `step_budget_exhausted` with its calls skipped and never run, while an `end_turn` answer on that same step is a decision.
- **Guard and typed failures (Task 3).** On a non-success extraction the final decision is escalate / `extraction_not_success`, `Overridden` is true when the model said approve or reject, and the model's decision is kept. Refusal, `max_tokens`, unparseable or schema-violating output, an outcome-cause pair the model may not use (13 of the 18 pairs) and any gateway failure (`cache_miss` included) are typed failures with no decision and no guard call. An empty `tool_use` answer is `schema_invalid`, never a tool round and never budget exhaustion, even on the last allowed step.

## Decisions Made

See `key-decisions`. The two worth restating: the guard always replaces the decision on a non-success status (so `decided_by` says who actually decided and `model_decision` records what the model alone would have done), and an unreadable guard result is a tool failure rather than a pass.

SDK schema members (the Task 1 action asked for this to be recorded): the MCP SDK 2.2.0 lists **exactly `type`, `properties` and `required`** at the top level of every tool input schema (the four case tools: `case_id` string required for three, empty `properties` for `get_policy`). `McpAgentToolbox` still builds each `LlmToolDefinition` from precisely those three members, and `The_sdk_lists_only_type_properties_and_required_in_every_tool_input_schema` fails if the SDK ever lists another, so nothing is dropped silently.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Two extra tool error kinds**
- **Found during:** Task 2 and 3 design
- **Issue:** The plan lists the error kinds is_error, protocol_error, transport_error, timeout, unknown_tool, not_read_only. Arguments that are not a JSON object, and a guard result with no readable status, had no kind, and trusting either would silently skip a safety check.
- **Fix:** Added `invalid_arguments` (toolbox) and `invalid_result` (guard). Both end in escalate / `tool_failed` through the normal path.
- **Files modified:** dotnet/src/Carimbo.Agent/AgentToolbox.cs, dotnet/src/Carimbo.Agent/AgentRunner.cs
- **Commit:** f0b6082, fb3c7c6

**2. [Rule 2 - Missing critical functionality] Bounded tool name in failures**
- **Found during:** Task 2
- **Issue:** `AgentToolFailure.Tool` can carry a model-invented tool name of any length, and a decision reason that echoed it would carry model text into a code-made decision (T-03.1-29).
- **Fix:** The name is clipped to 64 characters in the failure record, and a reason names a tool only when it is one of the four catalog tools.
- **Files modified:** dotnet/src/Carimbo.Agent/AgentRunner.cs
- **Commit:** f0b6082

**Total deviations:** 2 auto-fixed (both Rule 2). **Impact:** none on the plan's contracts; both add recorded error kinds and tighten messages.
