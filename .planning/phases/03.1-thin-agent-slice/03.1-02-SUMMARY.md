# Phase 03.1 Plan 02: the model seam carries tool turns, and the response cache replays them Summary

**The Carimbo gateway records now carry tool definitions, ordered content blocks and tool results, tool conversations are keyed by a second pinned canonical-JSON recipe (llm-cache-key-2) while every extraction request keeps its Phase 3 key, and tool_use answers are stored so a whole agent run replays at zero model calls.**

## Accomplishments

- LlmContracts.cs gains LlmContentKind, LlmToolCall, LlmContentBlock (with OfText, OfToolUse, OfThinking, OfRedactedThinking factories), LlmToolResult, LlmToolDefinition, LlmTurn.Blocks and ToolResults, LlmRequest.SystemPrompt and Tools, a nullable Document, LlmStopReason.ToolUse, and LlmResponse.Blocks plus a computed ToolCalls. All additive: no extraction call site changed.
- LlmCacheKey writes the exact v1 object when the request is extraction-shaped and a new llm-cache-key-2 object otherwise (system_sha256, nullable document, tools with name and two hashes, follow-ups with ordered blocks and tool results). Only SHA-256 of content enters the key.
- LlmCacheStore writes llm-cache-entry-2 with a response.blocks array, a nullable document_sha256 and a tool_count; it still reads llm-cache-entry-1 as a response with empty blocks.
- CachingLlmGateway stores EndTurn and ToolUse answers. The tracer proves the replay through the real CachingLlmGateway over CostAccountingLlmGateway over a counting double: two inner calls across both gateways, HttpAttempts 1 then 0, identical blocks, tool calls and cost on replay.
- Two v2 vectors were computed with Python hashlib before the C# produced them, and both matched on the first run. Pin A is the tracer's step 2 request (no document, system prompt, one tool, echoed text and tool_use blocks, one tool result). Pin B has a document, thinking and redacted_thinking blocks, an error tool result and a salt.

## Pin computation

The commands are in the scratchpad, outside the repo and outside the code under test. `python3 -I pin_v2.py` builds each canonical object as a Python dict, hashes every member with `hashlib.sha256(text.encode("utf-8")).hexdigest()`, serialises with `json.dumps(obj, separators=(",", ":"), ensure_ascii=False)` and hashes that string for the key. Pin A was then cross-checked with `printf '%s' "$(cat pinA.json)" | sha256sum`, which printed the same hex.

## Decisions Made

- The v1 writer is selected by a single predicate (document present, no system prompt, no tools, no follow-up blocks or tool results), so the Phase 3 keys and replay fixtures do not move.
- An empty-string system prompt is not "no system prompt": it selects the v2 recipe and hashes the empty string, so it keys differently from null.
- Entries written by this plan are never readable by a Phase 3 binary (entry_version 2), which is intended: the version constant makes a rollback visible rather than silent.
