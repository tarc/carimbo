# Phase 5 Plan 03: a stored run graded on the whole invoice

## Phase Goal

**As a** developer, **I want to** grade full-dataset runs field by field with confidence intervals, a silent-error rate and tagged failures, and compare any two runs case by case, **so that** I can tell real quality changes from noise.

This plan's slice: **As a** developer, **I want to** have `carimbo-evals grade` score every header field, item column and installment of a stored run, with rows matched by optimal assignment, **so that** a case is correct only when the whole invoice is right.

<objective>
Extend the offline grader from 27 header fields to the whole invoice. Add optimal row assignment, per-column grading, the `correct` flag and the `wrong` list, make numeric grading exact by default, and carry per-case dataset metadata into the case records.

Purpose: EVAL-03 and the numerator of the primary metric (D-01). Every later plan reads the `wrong` list and the `correct` flag. Bumps to `grader-003` and summary version 4 (D-03).
Output: normalize.py, matching.py, the extended grader and summary constants, and test_matching.py over all 154 cases.
</objective>

<assumption_delta_decision>
Signal: `chosen`, on "configurable tolerance" in the phase section.
Noun now primary: the grader's own tolerance, a parameter of a grading, stamped into each summary and part of what makes two runs comparable (D-18).
Decision: promote. Until now the grader's default was derived from the validator tolerance: `test_grader_default_tolerance_matches_the_vector_file` pinned them equal. D-03 ends that derivation. The grader owns its default of 0.00, the validator tolerance stays 0.01 in `data/vectors/validator-vectors.json` for .NET and the validators, and the old test is rewritten to assert independence, not removed silently.
Rationale: keeping the coupling and overriding the value would leave a test that says the opposite of the design.
Invariant test (accepted, Task 2): grading the same answer at 0.00 and at 0.01 differs exactly by the values flagged `within_cent`, so the two views really come from one grading.
</assumption_delta_decision>

Order `wrong` by true row then column order, then the extras. `stats` is `{true_rows, predicted_rows, matched, rows_all_correct, order_preserved, columns: {column: {correct, n}}}`, where `n` is the matched pairs and `order_preserved` is True when the matched true indices increase with the predicted index.
