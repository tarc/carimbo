# Phase 5 Plan 04: every wrong value tagged, and the grader proven on seeded corruptions

## Phase Goal

**As a** developer, **I want to** grade full-dataset runs field by field with confidence intervals, a silent-error rate and tagged failures, and compare any two runs case by case, **so that** I can tell real quality changes from noise.

This plan's slice: **As a** developer, **I want to** see each wrong value of a graded run labelled with what went wrong, from a versioned rule list that ground truth and seeded corruptions prove, **so that** failures feed an analysis instead of a pile of mismatches.

Implement failure-tags-1 as a pure ordered rule list over the graded diff, add the shared corruption catalogue, and prove the grader over all 154 cases: ground truth perfect, each corruption producing exactly its tag, row tests with exact precision and recall.

Purpose: EVAL-07 and EVAL-04.
Output: tags.py, corruptions.py, per-case tags in the grader, test_tags.py and test_selftests.py.

- `party_swap`: the case shows a crossover (predicted issuer CNPJ equals expected recipient tax id, or predicted recipient tax id equals expected issuer CNPJ, by `normalize_id`; or predicted issuer name equals expected recipient name, or the reverse, by `normalize_name`), and the value path starts with `issuer.` or `recipient.`.
- `merged_rows`: for each unmatched true row u and matched pair (p, t), column in (`total`, `quantity`): `p[col] == t[col] + u[col]` with `t[col]` non-zero. Tags the missing value of u and the matched pair's value at (t, col).
- `split_rows`: for each unmatched predicted row q and matched pair (p, t), column in (`total`, `quantity`): `p[col] + q[col] == t[col]` with `t[col]` non-zero. Tags the extra value of q and the matched pair's value at (t, col).
- `value_from_other_row`: a matched item value in columns `code, description, ncm, quantity, unit_price, total, icms_base, icms_amount, ipi_amount`, equal (by the column's own equality) to the same column of a different true row whose value differs from the expected one, and non-zero for a numeric column.
- `value_from_other_box`: a `totals.*` value equal to a different expected totals box, non-zero; or an item money column equal to another of `quantity, unit_price, total, icms_base, icms_amount, ipi_amount` of the same true row, non-zero.
- `thousands_misparse`: a numeric value (item numeric column, `totals.*`, installment `amount`), predicted non-zero, different from expected, with the same significant digits (`format(abs(d).normalize(), "f")` with the point removed, left zeros and right zeros stripped).
- `zero_for_blank`: a numeric value, predicted numerically zero, expected not.
- `digit_transposition`, `digit_substitution`, `digit_count`: over numeric values and id-like values (`access_key`, `issuer.cnpj`, `recipient.tax_id`, `issuer.ie`, `recipient.ie`, `number`, `series`, item `ncm`, `cst_csosn`, `cfop`, `code`, installment `number`), comparing uppercase strings of letters and digits only (numeric values through `format(d, "f")` first): same length with exactly two adjacent positions swapped; same length with exactly one position different; one character inserted or deleted.
- `text_near_miss`: paths `operation_nature`, `issuer.name`, `recipient.name` and item `code`, `description`, `unit`, with `difflib.SequenceMatcher(None, a, b, autojunk=False).ratio() >= 0.9` over `normalize_name` of both strings.
- `text_wrong`: any other string value on those paths, plus `issuer.uf`, `recipient.uf` and `recipient.tax_id_kind`.
- `tax_code_wrong`: item `cst_csosn`, `cfop` or `ncm` that missed the digit rules.
- `date_wrong`: `issue_date` or installment `due_date`.
A date is neither numeric nor id-like, so it never reaches a digit rule. All numeric equality is Decimal.
