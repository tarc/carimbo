# Phase 2 Plan 08: every extraction is validated, and the endpoint reports findings and attempts

## Phase Goal

**As a** developer, **I want to** have every extraction target the full DANFE-visible invoice, pass deterministic validators and be repaired within a bounded budget, **so that** extracted invoices carry hard guarantees before anything is measured at scale.

This plan's slice: **As a** developer, **I want to** post a DANFE to the eval endpoint and get the invoice back with its validator findings, its attempt record and a reproducible reference date, **so that** I can tell a clean extraction from a caught one in every stored run.

<objective>
Wire `InvoiceValidator` into the extractor and move the eval endpoint and the runner to contract version 2 (D-24): findings, the `validation_failed` outcome (CONTEXT D-14), an attempts list (D-15, one attempt until plan 02-09 adds repair), and the optional reference date (D-11).

Purpose: API-01 (the endpoint runs the same extraction and validation code as production and returns validator outcomes, attempts, tokens, cost, latency and trace id), EXT-04 (attempt records), VAL-01 and VAL-05 end to end.
Output: extractor, endpoint and composition changes; runner contract 2; e2e expectations for validated outcomes.
</objective>

<assumption_delta_decision>
The detector's pluralization cue ("alongside the result and trace ID", ROADMAP criterion 5) matches the real change here: one model call per extraction becomes a list of attempts.
- Primary noun: the attempt. Each model call is an `ExtractionAttempt` / `attempts[i]` record with its own output, findings, usage, cost and latency.
- Decision: promote. Response-level usage and cost are defined as sums over attempts, and stop_reason, model_returned and provider_message_id as the last answered attempt's values; they are derived views of the attempt list, not a separate single-call record kept alongside it. The single `Response` member of the Phase 1 ExtractionResult is removed.
- Invariant test (accepted): an endpoint test asserts that top-level usage and cost_usd equal the sums over attempts (and are null with a warning when an attempt is unpriced); plan 02-09 extends it to multi-attempt repairs.
</assumption_delta_decision>
