# Phase 2 Plan 03: a repair turn can reach the provider, with the PDF cached, proven live

## Phase Goal

**As a** developer, **I want to** have every extraction target the full DANFE-visible invoice, pass deterministic validators and be repaired within a bounded budget, **so that** extracted invoices carry hard guarantees before anything is measured at scale.

This plan's slice: **As a** developer, **I want to** send a follow-up repair turn through the existing gateway with the PDF block cached, and confirm live that the provider accepts the v2 schema, **so that** the repair loop (02-09) is built on a request shape the API is known to accept.

<objective>
Extend the provider seam additively for multi-turn conversations and the prompt-cache breakpoint (CONTEXT D-13: "The planner confirms that ILlmGateway can express multi-turn plus cache_control"), then run one small paid probe that settles RESEARCH assumptions A1, A2, A4 and A5 against the live API.

Purpose: the repair loop and the wider schema are the two places this phase can hit a provider-side dead end; both are checked here, before the loop and the endpoint are built on them.
Output: `LlmTurn`/`LlmTurnRole`, `LlmRequest.FollowUps`/`CacheDocument`, gateway support and wire tests, `LlmSpike --schema-probe`, `just schema-probe`, `docs/spikes/02-schema-probe.md`.
</objective>
