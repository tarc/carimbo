# Phase 2 Plan 13 (gap closure from UAT): the prompt, schema descriptions and DANFE mapping quote what the DANFE prints

## Phase Goal

**As a** developer, **I want to** have every extraction target the full DANFE-visible invoice, pass deterministic validators and be repaired within a bounded budget, **so that** extracted invoices carry hard guarantees before anything is measured at scale.

This plan closes UAT gaps G-02-1 and G-02-2 (both minor, linked, fixed together). The prompt `extract-002` and `docs/DANFE-MAPPING.md` were written from DANFE label conventions, not from what BrazilFiscalReport 1.2.0 prints. On the homologation DANFEs (every synthetic case is homologation by D-14), the DESTINATÁRIO name box prints a notice. The recipient name appears only in the RECEBEMOS DE receipt stub. Three totals labels differ from the print, and Simples invoices head the tax-code column CSOSN. The live Haiku 4.5 runs still read the name correctly. This is an accuracy fix, not a behaviour emergency.

<objective>
Make every text the model reads (prompt and model-facing schema descriptions) and the mapping doc quote the labels the skeleton DANFEs actually print. Bump the prompt version to extract-003 and pin each prompt text to its version, and add a pytest that checks the printed facts against the committed PDFs.

Purpose: measured quality needs the instructions and the documentation to describe the real document (DOM-02: the XML to DANFE mapping is documented), and needs every prompt change to be visible as a new version in the eval metadata (API-01 echoes prompt_version in effective and attempts).
Output: prompt extract-003, corrected schema descriptions with regenerated schema and Pydantic models, corrected docs/DANFE-MAPPING.md, python/tests/test_danfe_labels.py, and updated version pins.
</objective>
