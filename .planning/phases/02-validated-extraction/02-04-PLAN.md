# Phase 2 Plan 04: deterministic validators that return structured findings and never throw

## Phase Goal

**As a** developer, **I want to** have every extraction target the full DANFE-visible invoice, pass deterministic validators and be repaired within a bounded budget, **so that** extracted invoices carry hard guarantees before anything is measured at scale.

This plan's slice: **As a** developer, **I want to** run one call that checks an invoice's identifiers, access key, dates, items, taxes and totals and lists every problem as a structured finding, **so that** extraction (02-08), repair (02-09) and the ground-truth gate (02-07) share one deterministic rule set.

<objective>
Create `Carimbo.Validation`, a pure library (references Carimbo.Domain only) with the D-23 rule catalogue, and its test project that runs the shared vector file, per-rule tests and a never-throw loop.

Purpose: VAL-01..VAL-06. Validators are the deterministic layer (D-05) that later drives repair; they must be pure (reference date passed in, D-11), stable (rule ids end up in committed reports, D-10) and total (never throw, RESEARCH Pitfall 5).
Output: `dotnet/src/Carimbo.Validation/*`, `dotnet/tests/Carimbo.Validation.Tests/*`, both in `Carimbo.slnx`.

Rule catalogue and semantics (D-23, CONTEXT D-06..D-11, RESEARCH "Validator rule catalogue"; every id is a const in `RuleIds`):
- Identity: CNPJ_FORMAT, CNPJ_CHECK_DIGIT (issuer.cnpj; recipient.tax_id when 14 characters), CPF_FORMAT, CPF_CHECK_DIGIT (recipient.tax_id when 11 characters), TAX_ID_KIND_MISMATCH (recipient.tax_id_kind disagrees with the identifier length), UF_UNKNOWN (issuer.uf, recipient.uf not among the 27 UFs). Check digits are computed only after the pattern matched (ASCII − 48 is meaningful only for 0-9 and A-Z); 14 identical CNPJ characters and 11 identical CPF digits fail the check-digit rule.
- Access key (field access_key): KEY_FORMAT, KEY_CHECK_DIGIT (weights 2..9 from the right over the first 43 characters, remainder < 2 gives 0), then only when the format is valid: KEY_UF_MISMATCH (positions 0-1 vs the IBGE code of issuer.uf; skipped when issuer.uf is unknown), KEY_ISSUER_CNPJ_MISMATCH (6-19 vs issuer.cnpj), KEY_YEAR_MONTH_MISMATCH (2-5 vs issue_date as yyMM), KEY_MODEL_MISMATCH (20-21 vs 55), KEY_SERIES_MISMATCH (22-24 as an integer vs series), KEY_NUMBER_MISMATCH (25-33 as an integer vs number).
- IBGE UF codes: RO 11, AC 12, AM 13, RR 14, PA 15, AP 16, TO 17, MA 21, PI 22, CE 23, RN 24, PB 25, PE 26, AL 27, SE 28, BA 29, MG 31, ES 32, RJ 33, SP 35, PR 41, SC 42, RS 43, MS 50, MT 51, GO 52, DF 53.
- Dates: DATE_PLAUSIBLE (issue_date ≥ 2006-04-01 and issue_date.DayNumber ≤ referenceDate.DayNumber + 1, compared as integers so DateOnly.MaxValue cannot overflow); DUE_DATE_ORDER (installments[i].due_date ≥ issue_date).
- Items: ITEMS_EMPTY (field items); REGIME_CODE_MISMATCH (field items, 3- and 4-digit cst_csosn mixed); per item i in ascending order: ITEM_ARITH (items[i].total vs RoundHalfUp(quantity × unit_price)); ICMS by family from cst_csosn (3 digits: origin + CST, code = last 2; 4 digits: origin + CSOSN, code = last 3): taxed Normal 00, 20, 90 and Simples 900 → TAX_ARITH_ICMS (items[i].icms_amount vs RoundHalfUp(icms_base × icms_rate / 100)); not taxed Normal 40, 41, 50, 60 and Simples 101, 102, 103, 300, 400, 500 → TAX_NOT_TAXED_AMOUNT (icms_amount must be 0.00); any other code → TAX_CODE_UNSUPPORTED warning (items[i].cst_csosn), ICMS arithmetic skipped; TAX_ARITH_IPI for every item (items[i].ipi_amount vs RoundHalfUp(total × ipi_rate / 100); IPI base = item total, RESEARCH A7).
- Totals: TOTAL_SUM_PRODUCTS (Σ items.total vs totals.products_total), TOTAL_SUM_ICMS_BASE, TOTAL_SUM_ICMS, TOTAL_SUM_IPI (Σ of the item column vs the totals box), all within SumTolerance(items.Count); TOTAL_VNF_FORMULA (totals.invoice_total vs products_total − discount + icms_st_amount + freight + insurance + other_expenses + ipi_amount, within Tolerance).
- Installments: DUP_SUM (only when non-empty; Σ amount vs totals.invoice_total within SumTolerance(installments.Count)), severity error (D-23).
- ARITH_OVERFLOW: replaces the finding of any check whose multiplication, addition or subtraction overflows; its field is the field being checked.
- Severity: everything is Error except TAX_CODE_UNSUPPORTED (Warning).
- Expected and Actual are strings: amounts in invariant "0.00", dates "yyyy-MM-dd", check digits as computed and printed digits, identifiers and segments as text; "" when not applicable (for example UF_UNKNOWN expected "one of the 27 UF codes").
- Order: identity (issuer.cnpj, recipient tax id and kind, issuer.uf, recipient.uf), access key (in the listed order), dates (issue date, then installments by index), items (ITEMS_EMPTY, REGIME_CODE_MISMATCH, then each item by index: ITEM_ARITH, ICMS rule, TAX_ARITH_IPI), totals (in the listed order), DUP_SUM.

Execution environment: `devenv shell -- <cmd>` from the repo root; xUnit `Assert` only; explicit `'0' <= c && c <= '9'` style character checks (never `char.IsDigit`).
