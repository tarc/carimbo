# Phase 2 Plan 10: the reworked skeleton runs live with and without repair

## Phase Goal

**As a** developer, **I want to** have every extraction target the full DANFE-visible invoice, pass deterministic validators and be repaired within a bounded budget, **so that** extracted invoices carry hard guarantees before anything is measured at scale.

This plan's slice: **As a** developer, **I want to** run the three reworked cases live with repair enabled and disabled from one documented command, **so that** I see the full target, the validators and the repair loop work against the real model, and get a first look at what repair buys.

<objective>
Make the live skeleton recipe take the repair budget and the runner tolerate repair chains, then run the paid phase gate twice (CONTEXT D-19): `max_repairs` 2 and `max_repairs` 0, on `claude-haiku-4-5`, US$1.00 cap per run.

Purpose: the live proof of EXT-03, EXT-04 and API-01; scripted-model tests stay the CI proof (D-19). The 2-vs-0 comparison previews the Phase 6 repair ablation.
Output: recipe and runner changes; two recorded live runs described in the SUMMARY (run output stays git-ignored).
</objective>
