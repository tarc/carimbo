Design choice (planner, per WR-01): the verifier asked for integers disallowed plus a case-exactness check. The built-in converter, even with integers disallowed, still folds case and trims spaces when it reads a name, so a post-parse exactness check would have to be hand-listed per enum field. A small strict converter in the Domain enforces exactness for every enum at once, and building the schema node from the converter's own name table keeps parser and schema from drifting. The cost is that the exporter now sees a custom converter, which the existing custom-converter branch pattern already handles.
