# Phase 4 Plan 10: twin bytes no longer depend on SOURCE_DATE_EPOCH (gap closure G-04-2)

## Phase Goal

**As a** developer, **I want to** evaluate against a seeded dataset of at least 150 varied and deliberately hard invoices whose ground truth is proven valid, **so that** measured accuracy reflects realistic difficulty instead of a few clean cases.

This plan's slice: **As a** developer, **I want to** get the same twin bytes from `just dataset-check` on the GitHub runner as in my devenv shell, **so that** the committed dataset is reproducible where CI checks it, not only where it was built.

## Gap closed

- **G-04-2 (blocker, UAT test 3):** CI run 40915848246 failed `just py-check` on `test_scan.py::test_twin_bytes_leak_neither_key_nor_case_id_and_use_dct_without_a85` (twin lacks `D:19800101000000`) and `test_dataset_manifest.py::test_a_separate_process_building_cases_in_reverse_order_writes_the_committed_bytes` (nfe-0154 hash), so `just dataset-check` never ran. Root cause: reportlab 5.0.1 `TimeStamp` takes the PDF date from `SOURCE_DATE_EPOCH` when it is set and falls back to 946684800 (2000-01-01) in invariant mode; the date also seeds the document `/ID`. scan.py builds twins with `canvas.Canvas(..., invariant=1)` and never pins the date. The devenv shell exports `SOURCE_DATE_EPOCH=315532800`, so the committed twins carry `D:19800101000000`; ubuntu-latest sets nothing. Reproduced locally: `devenv shell -- uv run --project python env -u SOURCE_DATE_EPOCH carimbo-datagen dataset-check` reports exactly the 64 twin PDFs nfe-0091..nfe-0154.

## Design (verified by the planner before writing this plan)

reportlab 5.0.1 offers no parameter for the document date: `TimeStamp.__init__` reads `os.environ.get('SOURCE_DATE_EPOCH')` and, when it is set, uses `int(value)` as the time; `PDFDocument.__init__` creates the `TimeStamp` and seeds the `/ID` signature with `ascii(timestamp.t)`, so the committed `/ID` comes from the integer 315532800. Setting the variable to the string "315532800" for the duration of the canvas, and restoring the previous state afterwards, therefore reproduces the committed bytes. Planner probe on 2026-10-29: in processes started with the variable absent and with 1700000000, a scoped value of "315532800" rebuilt nfe-0091 (image_clean), nfe-0093 (rotation) and nfe-0146 (barcode_damaged) byte-identical to the committed files and left the process value as it found it; without the scope all three differed. With SOURCE_DATE_EPOCH=1700000000 and no scope, the text PDFs nfe-0001 and nfe-0088 (two pages) still matched the committed bytes and only the twin differed, so fpdf2 (whose date danfe.py pins) and fontTools do not put the variable into the text PDFs. Only `PDFDocument.__init__` reads the time on this path (`PDFDate` reuses the document's `TimeStamp`).

Rejected: overwriting reportlab's private `_doc._timeStamp` and re-seeding its `signature` after construction (copies a private /ID recipe that a reportlab bump could change silently); exporting `SOURCE_DATE_EPOCH` in the justfile or ci.yml (pytest, direct CLI calls and a reviewer's shell would still differ); recording PDF_EPOCH in `scan_parameters()` (changes manifest.json, so this plan could no longer prove that no dataset byte moved).

<objective>
Pin the twins' PDF date in code to the committed epoch 315532800 regardless of `SOURCE_DATE_EPOCH`, prove it with subprocess builds that start without the variable or with another value and must match the committed hashes, and prove that `just dataset-check`, `just datagen-check` and `just py-check` pass with the variable unset, while no byte under data/ changes.

Purpose: DATA-06 and CONTEXT D-13 (byte-identical regeneration on CI Linux x64), UAT gap G-04-2.
Output: PDF_EPOCH and the scoped pin in scan.py; environment-variant tests in test_dataset_manifest.py and test_scan.py.
</objective>
