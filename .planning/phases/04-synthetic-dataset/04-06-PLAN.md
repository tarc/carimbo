# Phase 4 Plan 06: long text that wraps but never truncates, and confusable values, checked against the printed DANFE

## Phase Goal

**As a** developer, **I want to** evaluate against a seeded dataset of at least 150 varied and deliberately hard invoices whose ground truth is proven valid, **so that** measured accuracy reflects realistic difficulty instead of a few clean cases.

This plan's slice: **As a** developer, **I want to** have invoices whose names and descriptions wrap and whose values are easy to transpose or swap, with a test that every graded string is printed exactly as the ground truth says, **so that** hard cases measure reading errors and never a mismatch between the page and the answer key.

<objective>
Add the two remaining hard traits of CONTEXT D-04: long names and descriptions that wrap on the DANFE (capped so nothing is truncated, D-05) and confusable values (near-identical adjacent rows, totals with many digits, similar parties in one UF). Prove D-05 with a test that every graded string of each text-layer PDF's XML appears in its printed text, and prove exact arithmetic dataset-wide.

Purpose: DATA-02 (deliberately hard cases) and DATA-04 (ground truth equals what is printed and passes the validators exactly), per CONTEXT D-04 and D-05; RESEARCH Pitfall 3 (a token longer than the column is broken mid-token, so words stay at most 20 code points and the comparison removes whitespace) and Pitfall 8 (value caps). BrazilFiscalReport formats numbers through float (`brazilfiscalreport/utils.py` format_number), which is exact only while values stay under the caps above, so the test formats expected values from the XML Decimal, independently of the renderer.
Output: widened quota.py and dataset_spec.py, test_dataset_text_equals_xml.py, exact-arithmetic tests, regenerated data/dataset.
</objective>
