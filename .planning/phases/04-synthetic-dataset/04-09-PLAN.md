# Phase 4 Plan 09: the DATA-04 ground-truth gates over every manifest case (.NET validators and JSON Schema)

## Phase Goal

**As a** developer, **I want to** evaluate against a seeded dataset of at least 150 varied and deliberately hard invoices whose ground truth is proven valid, **so that** measured accuracy reflects realistic difficulty instead of a few clean cases.

This plan's slice: **As a** developer, **I want to** have CI fail whenever any dataset case's ground truth fails the exported JSON Schema or the .NET validators, **so that** every case the quota table adds in plans 04-05 to 04-07 is proven valid the moment it is generated.

<objective>
Generalize the ground-truth gate from the three hard-coded skeleton cases to any manifest, and run it over every case of data/dataset (the two tracer cases of plan 04-04 now, 154 cases at the end of the phase): the .NET mapper plus validators with zero error findings, and the Python JSON Schema plus strict-model validation, both parametrized from the manifest. This work was split out of plan 04-04 (checker iteration 1, file and context budget); it runs before the quota widens so plans 04-05 to 04-07 verify every regeneration against it.

Purpose: DATA-04 per CONTEXT D-18 (the .NET GroundTruthGateTests mapping plus zero validator error findings, warnings allowed, and the Python JSON-Schema validation of the mapped ground truth, both in CI, iterating the manifest so nothing is skipped), and ROADMAP Phase 4 success criterion 3. The gates run in CI through the existing `just dotnet-check` and `just py-check` steps, so no workflow change is needed.
Output: GroundTruthManifest.cs, DatasetGroundTruthGateTests.cs, GroundTruthGateTests.cs refactored onto the helper, test_dataset_ground_truth.py.
</objective>
