# Phase 3 Plan 01: request-hash cache key, store and mode matrix, proven by a zero-call replay

## Phase Goal

**As a** developer, **I want to** replay eval reruns from a request-hash cache and see every model call as a costed span in a local trace viewer, **so that** I can iterate on prompts and graders without paying twice and can trace any case back to its model calls.

This plan's slice: **As a** developer, **I want to** have a model call answered from a local request-hash cache on rerun, **so that** a replay makes zero model calls and still reports the latency and cost the original call had.

<objective>
Build the D-19 response cache in Carimbo.Llm as a decorator over ILlmGateway (key, file store, modes) and prove it end to end through the decorator stack: a read_write call stores the answer and a fresh read_only gateway on the same directory replays it with zero model calls. Then pin the key and harden the mode matrix.

Purpose: the LLM-04 key and the LLM-05 core, and the "prompt version is part of the cache key" half of EXT-05 (prompt_version and repair_prompt_version are key fields). Plan 03-03 wires the cache into the Api, on by default in Development and Eval (D-27), and makes the extractor stamp the key fields; every later Phase 3 plan builds on these types.
Output: Carimbo.Llm/Cache/*, cache contract types in LlmContracts.cs, CachingGatewayTests and CacheKeyTests, the updated request-property guard in ExtractorTests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cache directory on disk → CachingLlmGateway | Entry files are read back as model answers; a local file is less trusted than the provider response it replaces |
| Request fields → cache key | Request-derived values feed the key and the file name |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | LlmCacheStore.TryRead (poisoned or corrupt entry) | medium | mitigate | Entries carry entry_version and key; a mismatch, unparseable JSON or IO error is a miss; content is only parsed as data, never executed; the directory is local and git-ignored; Task 2 tests the three malformed shapes |
| T-03-02 | Tampering | file name derived from request input (path traversal) | high | mitigate | The file name is only the 64-hex SHA-256 digest validated by ^[0-9a-f]{64}$ before any path is built; model, salt and case id never reach a path |
| T-03-04 | Information disclosure | entry files | low | accept | Entries hold model output of synthetic invoices only (D-14) in git-ignored .cache/; prompt, schema, document bytes, key and base URL are never stored (Task 2 test asserts the sentinels are absent) |
| T-03-05 | Repudiation | a replay presented as a fresh call | medium | mitigate | A hit reports HttpAttempts 0 and Cache.Status Hit; only end_turn answers are stored, so a truncated or refused outcome can never be replayed as an answer |
| T-03-SC | Tampering | package installs | low | mitigate | No package is added in this plan |
</threat_model>
