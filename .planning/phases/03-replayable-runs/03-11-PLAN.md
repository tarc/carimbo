# Phase 3 Plan 11: repair calls are labelled in the trace, and the README lists the real cache key (gap closure)

## Phase Goal

**As a** developer, **I want to** replay eval reruns from a request-hash cache and see every model call as a costed span in a local trace viewer, **so that** I can iterate on prompts and graders without paying twice and can trace any case back to its model calls.

This plan's slice: **As a** developer, **I want to** see in the trace viewer which prompt each model call used, **so that** a repair call is told apart from the first extraction call by its label, not by its position, and the label agrees with the eval record.

## Gaps closed

- **G-03-1 (major, UAT test 1):** repair-call spans carry `carimbo.llm.prompt_version` extract-003 while the eval record says repair-001. Root cause: `TracingLlmGateway` tags only `LlmRequest.PromptVersion`; the extractor sends the extraction version there on every call and puts repair-001 in `RepairPromptVersion` (InvoiceExtractor.cs lines 261 and 276-277), which the span never reads.
- **G-03-2 (minor, UAT test 2):** README.md line 31 lists a cache-key field the key does not contain and omits max tokens and the replicate salt (LlmCacheKey.cs lines 50-70 are the real recipe).

## Design choice for G-03-1 (D-33)

Keep `carimbo.llm.prompt_version` as the extraction prompt version on every span, and add one allowlisted attribute `carimbo.llm.repair_prompt_version`, set only when the request carries a repair prompt version. Reasons:

1. The span mirrors `LlmRequest` field for field, so the tracing decorator stays observe-only and Carimbo.Llm learns no extraction rule (it does not know what an attempt is).
2. The two names and meanings match the cache-key fields `prompt_version` and `repair_prompt_version` (D-27) and the response's `effective.prompt_version` and `effective.repair_prompt_version`, so one vocabulary covers key, record and trace.
3. A repair call really sends both prompts: the first user turn holds the extraction prompt text and the follow-ups carry the repair feedback. Both labels belong on it.
4. The existing attribute keeps its meaning, so the traces exported by the 03-10 live run read the same way, and repair spans become searchable by the new tag.

Rejected: switching `carimbo.llm.prompt_version` to the per-call value. It would change an already exported attribute's meaning, diverge from the cache-key and `effective` names, move the extractor's `index == 0 ? PromptVersion : RepairPromptVersion` rule into the gateway, and drop the extraction version from repair spans.

The per-call label that `attempts[].prompt_version` reports is therefore `carimbo.llm.repair_prompt_version` when present, else `carimbo.llm.prompt_version`. The tests assert exactly that equality.

Not in scope (UAT test 1 observations the user did not raise as gaps): the "Incomplete" trace flag from the runner's unexported parent span, the cached-token difference in `gen_ai.usage.input_tokens`, and `GET /healthz` traces. No new live seeding run is scheduled: every check here is offline, and the in-memory exporter tests stand in for Jaeger.
