### Auto-fixed Issues

**1. [Rule 1 - Bug] Golden traceparent collided with TracingWiringTests**
- **Found during:** Task 2 (first full `dotnet test --project tests/Carimbo.Api.Tests`)
- **Issue:** I reused the fixed trace id 4bf92f3577b34da6a3ce929d0e0e4736 that `TracingWiringTests` also uses. That class counts exported chat spans for the trace id and test classes run in parallel, so the golden scenarios' spans made `An_inbound_unsampled_traceparent_still_exports_the_chat_span_on_the_inbound_trace_id` see two spans instead of one. It passed in isolation and failed in the full run.
- **Fix:** The goldens use trace id 0af7651916cd43dd8448eb211c80319c (the W3C example), with a comment explaining why; fixtures regenerated.
- **Files modified:** `dotnet/tests/Carimbo.Api.Tests/GoldenResponseTests.cs`, `data/contract/eval-responses/*.json`
- **Verification:** three consecutive full runs of the Api test project passed, then the whole `just check`.
- **Committed in:** `d3efd78`

**2. [Rule 3 - Blocking] `PostRawAsync` could not send a traceparent**
- **Found during:** Task 2 (overrides scenario)
- **Issue:** The overrides scenario must post the request file verbatim and still get a deterministic `trace_id`, but `TestHost.PostRawAsync(body, key)` always sent no traceparent, so the response would carry a random trace id.
- **Fix:** Added an optional `traceparent` parameter (default null, so every existing call is unchanged). The file is not in the plan's `files_modified`.
- **Files modified:** `dotnet/tests/Carimbo.Api.Tests/EvalEndpointTests.cs`
- **Verification:** the existing 198 Api tests pass unchanged.
- **Committed in:** `84f693a`
