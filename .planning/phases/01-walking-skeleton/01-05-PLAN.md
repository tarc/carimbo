  <action>
In namespace `Carimbo.Extraction`, add `public static class ModelSchemaProjector` with `public static JsonObject Project(JsonObject canonical)` and `public sealed class SchemaProjectionException : Exception`. Implement the rules from research Pattern 3. `Project` deep-clones the input and never mutates it, then walks every schema node (properties, items, anyOf members, $defs entries) and preserves key order. It keeps `pattern` and `format: date`. Research marks pattern support as [ASSUMED] until the spike; if the spike in 01-10 finds the API rejects `pattern`, plan 01-12 adds the documented fallback here. Phase 1 has none of the stripped keywords; the rules exist and are tested so Phase 2 additions are handled.

Add `public static class SchemaBudget` with `public const int MaxOptional = 24`, `public const int MaxUnion = 16`, `public sealed record Counts(int Optional, int Union)`, `public static Counts Count(JsonObject schema)` and `public static void EnsureWithin(JsonObject schema)`. EnsureWithin throws `SchemaBudgetExceededException` (also in this file), and its message states both counts and both limits. Counting follows the docs wording quoted in research: optional means each property not listed in its object's `required`, and union means each property schema using `anyOf` or a `type` array. Expand each `$ref` per use, which is conservative.

Create the xUnit v3 project `dotnet/tests/Carimbo.Extraction.Tests` (OutputType Exe, xunit.v3 via CPM, ProjectReference to Extraction) and add it to `dotnet/Carimbo.slnx`. Write `SchemaProjectionTests.cs` with the behaviours above. Build synthetic schemas in code with JsonNode.Parse so the counter's failure path is proven; a counter that cannot fail proves nothing.
