# Phase 1 Plan 08: Typed outcomes and a locked-down eval endpoint, under test

## Phase Goal

**As a** developer, **I want to** generate a few synthetic DANFEs, extract them live through the .NET eval endpoint and grade the stored results from Python, **so that** the whole measurement loop runs end to end on real code before any breadth is added.

<objective>
Harden the two contracts the tracer created and prove them with unit and integration tests. The extractor's outcome mapping (EXT-01, EXT-02) is tested against a capturing fake gateway. The eval endpoint's availability rules, static-key auth, input validation, size limit, trace-ID propagation and concurrency independence (API-03) are tested on TestServer.

Purpose: these are the guarantees the live run relies on. Typed failures stay distinct from quality failures, and the endpoint cannot become a free model proxy.
Output: `EvalEndpoint.cs` (moved out of Program.cs), the `Carimbo.Api.Tests` project, and `ExtractorTests.cs`.
</objective>
