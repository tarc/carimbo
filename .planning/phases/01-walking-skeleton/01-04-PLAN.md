# Phase 1 Plan 04: Canonical JSON Schema exported from the C# records

## Phase Goal

**As a** developer, **I want to** generate a few synthetic DANFEs, extract them live through the .NET eval endpoint and grade the stored results from Python, **so that** the whole measurement loop runs end to end on real code before any breadth is added.

<objective>
Make the C# records a provable source of truth. Test the Domain's purity and wire behaviour, export the canonical JSON Schema deterministically with a pure exporter, commit it with a staleness gate, and record the accepted DECISIONS D-03/D-07/D-15 refinements in `docs/DECISIONS.md`.

Purpose: after this plan a developer can regenerate the schema with one command and any drift fails `dotnet test`. Plan 01-05 projects this schema for the model, and plan 01-09 generates Pydantic models from it.
Output: `CanonicalSchema`, the `SchemaExport` tool, the committed `schema/invoice.schema.json`, the `Carimbo.Domain.Tests` project, and the D-18..D-20 entries.
</objective>

  <action>
In `Carimbo.Domain`, add `public static class CanonicalSchema`. It is pure and uses BCL only, through System.Text.Json.Schema. Members:
- `public const string Draft = "https://json-schema.org/draft/2020-12/schema"`
- `public static JsonObject Export()`
- `public static string ExportJson()`
- `public static string Serialize(JsonNode node)`. It writes indented JSON with `NewLine = "\n"`, `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` and a single trailing "\n". Plan 01-05 reuses it for the model-facing schema.

Implement the export as research Pattern 2 describes. Call `JsonSchemaExporter.GetJsonSchemaAsNode(Wire.Options, typeof(Invoice), options)` with `TreatNullObliviousAsNonNullable = true` and a `TransformSchemaNode` that:
1. checks `ctx.TypeInfo.Type == typeof(Money)` BEFORE any "is object" guard and returns `{"type":"string","pattern":Patterns.Money}`, with no title;
2. copies `DescriptionAttribute` → `description` and `RegularExpressionAttribute.Pattern` → `pattern` from `ctx.PropertyInfo?.AttributeProvider?.GetCustomAttributes(false)`;
3. sets `additionalProperties: false` and `title = <Type.Name>` on object schemas.

Then run a post-pass that hoists every non-root titled object into `$defs/<Title>` and replaces it with `{"$ref":"#/$defs/<Title>"}`. Build fresh JsonObject/JsonArray nodes and `DeepClone()` leaves; never re-parent a node that already has a parent, because that throws. Sort `$defs` ordinally. Prepend `$schema` = Draft at the root. Construct no new serializer options for export: Wire.Options is the single source.

Create the console tool `dotnet/tools/SchemaExport` (OutputType Exe, IsPackable false, IsTestProject false, ProjectReference to Domain) and add it to `dotnet/Carimbo.slnx`. The tool finds the repo root by walking up from the current directory to the folder containing `dotnet/Carimbo.slnx`. By default it writes `schema/invoice.schema.json` as UTF-8 without BOM, with LF endings (`new UTF8Encoding(false)`). With `--check` it writes nothing, compares the expected text with each committed file, prints the stale paths and exits 1 when any differ. Run it once to create `schema/invoice.schema.json`.

Write `SchemaSnapshotTests.cs` with the behaviours above. It locates the repo root the same way from `AppContext.BaseDirectory`.

  - the canonical JSON Schema is exported from the C# records by the pure `CanonicalSchema` exporter and committed as `schema/invoice.schema.json`;

- `## D-19 Request-hash cache keys, modes and reporting (refines DECISIONS D-07)`. **Phase:** 3. **Decision:**
  - the cache key is SHA-256 over the canonical final request: model, parameters, schema hash, prompt version, PDF SHA-256 and a replicate salt;
  - modes are read-write, read-only (replay) and refresh;
  - hits report the original latency and cost, and summaries show incurred versus notional cost and the hit rate;
  - truncated or refused responses are never cached;
  - the production configuration runs with the cache off.

  **Rationale:** current models reject sampling controls, so the cache is the reproducibility mechanism, and a cache that hides cost or variance would corrupt measurements. **Rejected:** the built-in distributed-cache chat client (no control over the key, no original cost).
