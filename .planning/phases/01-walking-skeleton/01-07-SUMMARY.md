# Phase 1 Plan 07: Committed skeleton cases from one seeded command Summary

**`carimbo-datagen build` writes three seeded XML+PDF case pairs and a hash manifest atomically, `check` regenerates and compares bytes, and the committed `data/skeleton` is proven byte-identical to a regeneration by a default-suite test.**

## Performance

- **Duration:** about 4 min (18:26 to 18:30 UTC)
- **Tasks:** 2 (both auto, 2 commits)
- **Files:** 1 module created, 1 test file extended, 7 data files committed

## Accomplishments

- `cli.py` provides the typer app (`no_args_is_help`) with `build` and `check`, and `build_dataset`, which tests call directly. Files are written to `<name>.tmp` and moved with `os.replace`. The PDF goes through `render_danfe` straight to the temporary name.
- `manifest.json` carries `dataset`, `dataset_version` `skeleton-001`, `master_seed`, `python` `3.12`, `generator` (carimbo 0.1.0, brazilfiscalreport 1.2.0, fpdf2 2.8.9, python-barcode 0.16.1, faker 40.40.0, lxml 6.1.3 from `importlib.metadata`) and the case list sorted by id with SHA-256, page counts and tags.
- Committed cases: case-001 (1 page, numeric CNPJ), case-002 (1 page, alphanumeric CNPJ), case-003 (2 pages, 80 items). A second `build` run left every file hash unchanged, and `carimbo-datagen check` exits 0.
- Four new tests in `test_datagen.py`: committed-vs-regeneration (exact file set plus bytes), manifest hashes and page counts against the files, no machine-specific values in the manifest, and a `check` command run against a deliberately tampered copy (exit 1, names `case-001.pdf` and `case-002.xml`, does not name `case-003.pdf`).
- Final run: `pytest python/tests` gives 48 passed (3 deselected e2e/live). ruff check, ruff format --check and pyright are clean.

## Open Item: assumption A9 (uv-managed interpreter bytes)

Byte identity was verified in-process, across a fresh interpreter (01-06), across two consecutive `build` runs, and through `check`, all on this host's Nix CPython 3.12.15. Whether a uv-managed CPython 3.12 (the CI runner) produces the same PDF bytes could not be tested here because interpreter downloads are disabled and none is installed. `test_committed_skeleton_matches_regeneration` is the alarm: if the first CI `py-check` run fails on a PDF hash, the documented fallback is `set_compression(False)` in `danfe.py`, followed by a deliberate regeneration recorded as a deviation. Never commit regenerated bytes silently, because PDF SHA-256 values become cache-key inputs (the task's reversibility rating is costly).
