  <action>
All types live in namespace `Carimbo.Domain` and use only BCL namespaces: System, System.ComponentModel, System.ComponentModel.DataAnnotations, System.Globalization, System.Text.Json, System.Text.Json.Serialization, System.Text.Json.Serialization.Metadata, System.Text.RegularExpressions.

`Invoice.cs`:
- `public static class Patterns` with consts `AccessKey = "^[0-9]{6}[A-Z0-9]{12}[0-9]{26}$"` (44 characters, admits the alphanumeric form per D-03), `Cnpj = "^[A-Z0-9]{12}[0-9]{2}$"` and `Money = "^-?[0-9]+\\.[0-9]{2}$"`. Use explicit `[0-9]` character classes, never the digit shorthand class, because in .NET that class also matches non-ASCII digits.
- The D-01 subset as a positional record: `public sealed record Invoice(string AccessKey, int Number, int Series, DateOnly IssueDate, Party Issuer, Party Recipient, Money TotalAmount)`. `AccessKey` carries `[property: Description("44-character NF-e access key (chave de acesso), digits and uppercase letters only, no spaces")]` and `[property: RegularExpression(Patterns.AccessKey)]`. `Number` and `Series` are `int` per research Open Question 2.
- `public sealed record Party(string Cnpj, string Name)`. `Cnpj` carries `[property: Description("CNPJ without punctuation: 12 alphanumeric characters plus 2 check digits")]` and `[property: RegularExpression(Patterns.Cnpj)]`. `Name` carries a Description saying "Company name exactly as printed".
- Per D-02, a pure `Decision` record: `public enum DecisionOutcome { Approve, Reject, Escalate }` and `public sealed record Decision(DecisionOutcome Outcome, string Reason)`. No type reachable from `Invoice` references `Decision`, so it never enters the exported extraction schema.

`Wire.cs`:
- `[JsonConverter(typeof(MoneyJsonConverter))] public readonly record struct Money(decimal Amount)`. It has `public static Money Parse(string text)`, which throws `FormatException`. That method first matches `Patterns.Money` with a compiled Regex, then calls `decimal.Parse(text, NumberStyles.AllowLeadingSign | NumberStyles.AllowDecimalPoint, CultureInfo.InvariantCulture)`. It also overrides `ToString()` to `Amount.ToString("0.00", CultureInfo.InvariantCulture)`. Research Pitfall 4 showed that the default NumberStyles accepts "12,34" as 1234, and this ordering closes that hole.
- `public sealed class MoneyJsonConverter : JsonConverter<Money>`. It reads only JSON strings, turns a FormatException or any non-string token into a `JsonException`, and writes the two-decimal string.
- `public static class Wire` with a `public static JsonSerializerOptions Options { get; }` built once. Construct it explicitly and do not start from the ASP.NET web defaults preset, which turns numbers into string-or-number unions (CLAUDE.md "What NOT to Use"). Set PropertyNamingPolicy `JsonNamingPolicy.SnakeCaseLower`, RespectNullableAnnotations `true`, RespectRequiredConstructorParameters `true`, UnmappedMemberHandling `JsonUnmappedMemberHandling.Disallow`, TypeInfoResolver `new DefaultJsonTypeInfoResolver()` (research Pitfall 3) and the converter `new JsonStringEnumConverter(JsonNamingPolicy.SnakeCaseLower)`. Call `MakeReadOnly()`.
- An XML doc comment on `Wire.Options` says it is the single options object for schema export (plan 01-04) and for parsing model output (plan 01-03), so the schema describes exactly what is accepted.
