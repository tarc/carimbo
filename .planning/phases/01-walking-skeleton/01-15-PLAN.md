# Phase 1 Plan 15 (gap closure): a cost cap that sees every possibly-paid call, and a grader and resume that survive real JSONL

## Phase Goal

**As a** developer, **I want to** generate a few synthetic DANFEs, extract them live through the .NET eval endpoint and grade the stored results from Python, **so that** the whole measurement loop runs end to end on real code before any breadth is added.

<objective>
Close the Python findings that 01-VERIFICATION.md asks to fix "in the same pass" because they weaken ROADMAP success criterion 5 (bounded concurrency, cost cap, resumable runner; offline grading):

1. WR-02 (EVAL-01, compounds CR-01): `runner.py` only charges completed records against the cap. A harness error (HTTP 5xx, a timeout, a reset after the server already called the model) may have been paid for, yet adds nothing; `--resume` re-runs it and can pay again without the cap noticing. Charge `reserve_usd` for every harness error that may have reached the provider, live and on resume (every prior record, not only the last), and report the assumed amount separately. This keeps the D-09 caps (US$1 per run, US$5 per phase) honest.
2. WR-01 (EVAL-02): the grader splits `cases.jsonl` with the Unicode-aware `str` line splitter, so a raw model output containing U+2028, U+2029 or U+0085 (which `json.dumps(..., ensure_ascii=False)` leaves unescaped) makes the whole run ungradable. Split on `"\n"` only, the runner's own delimiter.
3. WR-05 (EVAL-01, cheap and co-located in the same files): a corrupt middle line makes `--resume` crash with a traceback and exit 1, outside the documented 0/2/3/4 exit codes. Raise a named error and exit 2.

Purpose: the measurement loop must stay bounded in spend and gradable on real model output.
Output: changes to `runner.py`, `cli.py`, `grader.py` and their tests. No dependency, lockfile or record_version change (the new `http.error_type` key and `assumed_usd` field are additive).
</objective>
