# Quick 261106-5r4: McpAgentToolbox connect budget Summary

`McpAgentToolbox` now bounds `ConnectAsync` with its own optional `connectTimeout`, so the 500 ms call budget no longer has to cover a cold-start MCP handshake in `A_tool_that_outlives_the_call_timeout_is_a_timeout_on_the_real_session`.

## Changes

- `AgentToolbox.cs`: new last constructor parameter `TimeSpan? connectTimeout = null`. `_connectTimeout = connectTimeout ?? callTimeout ?? DefaultTimeout`, so when `connectTimeout` is not given it equals `callTimeout`, which defaults to 30 s (`DefaultTimeout`). `ConnectAsync` uses `linked.CancelAfter(_connectTimeout)`; the `Session` stays on `_callTimeout`. Production (`Program.cs`) passes only `callTimeout`, so its behaviour is unchanged and no file under `Carimbo.Api`, `AgentSettings` or `AgentRunner` moved.
- `AgentToolboxFaultTests.cs`: the flaky test connects on `GenerousTimeout` (30 s) and calls on `ShortTimeout` (500 ms), with a 10 s `Guard()` token on the call. Two new tests, using a `SilentHandler` that never answers, pin that the connect budget is independent of the call budget and that the default is the call timeout. No retry loop or sleep added.
